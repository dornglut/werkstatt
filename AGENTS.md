# Werkstatt Agent Contract

## Start here

1. Read [README.md](README.md).
2. Read [ARCHITECTURE.md](ARCHITECTURE.md).
3. Read [ROADMAP.md](ROADMAP.md).
4. Open the active program issue and active child issue identified there.
5. Verify the exact accepted `main` revision, task branch, pull request head, and unresolved review findings before editing.

## Authority

Use this order when sources disagree:

1. code and executable tests for current behavior;
2. accepted repository ADRs and architecture documents for durable local decisions;
3. accepted organization ADRs and standards for Dornglut-wide policy;
4. the active owning GitHub issue for authorized work;
5. the repository roadmap for durable phase order;
6. the pull request for the exact proposed delivery and review evidence;
7. generated packets, execution summaries, dashboards, and reports as derived or historical material only.

Correct the authority that owns a disputed fact before continuing work that depends on it.

## Current phase

The repository is in W0 product and architecture investigation.

W0 permits documentation and issue work only. It does not authorize Rust implementation, an execution daemon, a database schema, a Codex or model dependency, GitHub write automation, a Runenwerk frontend, or autonomous delivery.

## Work rules

- Work from the current accepted `main` revision on one bounded task branch.
- Keep one active writer per branch and workspace.
- Preserve explicit scope, non-goals, stop conditions, and exit gates from the owning issue.
- Treat humans, agents, scripts, and services as actors with explicit roles and capabilities; do not grant authority merely because an actor can perform an operation.
- Keep project authority, generated assistance, temporary execution state, and independent validation separate.
- Do not create generated or operational artifacts as parallel issue, roadmap, architecture, or validation authority.
- Do not introduce source-writing validation workflows or direct protected-branch writes.
- Do not turn issue or model text into arbitrary command authority.
- Keep each tracked text file below 131,072 raw bytes unless an accepted issue authorizes an exception and another execution path is available.

## Delivery

A documentation change must report:

- accepted base revision;
- exact reviewed branch head;
- files changed;
- links and authority inspected;
- validation performed and validation unavailable;
- unresolved findings;
- explicit next authorized action.

Use draft pull requests until the owner explicitly accepts review readiness. Do not merge without explicit owner authorization.
